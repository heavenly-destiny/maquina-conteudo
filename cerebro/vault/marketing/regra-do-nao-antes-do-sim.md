# A regra do "não" antes do "sim"

Ao abrir uma demanda de teste para o time (criativo, copy, tráfego), definir primeiro o que **não pode** ser feito, em vez de listar positivamente o que deve ser feito. Dizer "faça isso, faça aquilo" enviesa o time para uma única direção; dizer "não pode usar essa ferramenta, não pode usar esse formato" elimina só os caminhos ruins e deixa todo o resto do espaço de possibilidades livre para o time explorar.

É uma aplicação prática do princípio de inversão (pensar primeiro no que evitar, não no que perseguir) aplicado a briefing de equipe — útil sempre que a variável certa a testar ainda não é óbvia (ex.: quando um canal muda o algoritmo e ninguém sabe ainda o que volta a funcionar).
